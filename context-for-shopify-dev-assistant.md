I'm working on a heavily customized Dawn-based Shopify OS 2.0 theme (Shahana Collection) that implements an "Immersive Store" experience. The 2D storefront lives at `/` (`templates/index.json`) and the 3D experience lives at `/pages/immersive` (`templates/page.immersive.json`). The 3D page uses a single WebGL canvas (Three.js, loaded from `assets/three.min.js`) with depth maps for parallax across five rooms: `storefront → lounge → designer_houses / occasions / featured_collections`. Room config (texture URLs, hotspots) is hardcoded in `STORE_ROOMS` in `assets/immersive-store.js` and overridden at runtime by a `<script id="immersive-rooms-config" type="application/json">` block rendered by `sections/immersive-canvas.liquid`. Hotspots navigate between rooms, open collection/product glass panels via the Section Rendering API (`?section_id=glass-panel` / `?section_id=glass-product`), or trigger per-room editorial overlays (`enterEditorialMode(roomKey, triggerEl)`). Editorial content is fetched via Section Rendering using the `data-section-id` of the matching `sections/immersive-editorial.liquid` instance and injected into `#immersive-editorial-overlay`. The immersive canvas section also owns the wishlist panel (`#immersive-wishlist-panel`), onboarding overlay (`#immersive-onboarding`), and cookie consent banner (`#immersive-cookie-banner`). Bridge CTAs on all 2D pages use `snippets/immersive-bridge-btn.liquid` (`data-immersive-bridge`) and `assets/bridge-behavior.js` handles device/connection-aware messaging. The preference banner in `layout/theme.liquid` appears on non-immersive pages when `immersive_preferred_mode = '3d'` is set in localStorage. All CSS is in `{% stylesheet %}` blocks (BEM: `.immersive-*`) or `assets/immersive-theme.css` (page.immersive only). All JS is vanilla, in `assets/immersive-store.js` — no build step. I need help making changes and debugging within this architecture without replacing it with a standard theme layout.
